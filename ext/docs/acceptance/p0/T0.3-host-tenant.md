# T0.3 验收：仅靠 H2 + H5 让品牌 Host 返回品牌页

- 日期：2026-11-13
- 基线：官方 `v1.0.0-rc.50`
- 结论：**通过**。两个挂载点（合计官方区 5 行）足以实现按 Host 的租户隔离与品牌页渲染。

## 环境

- 二进制：从本仓库源码 `go build -p 2 -o cmh-gateway-proto.exe .` 构建（含 H2/H5 补丁）
- 数据库：SQLite 临时库；`web/dist` 使用一个只含 `OFFICIAL_INDEX` 的占位 index.html（构建后删除，未入库）
- 租户映射：`CMH_BRAND_PROTOTYPE_HOSTS=demo.brand.test=brand-demo`（原型用环境变量，T2 改为数据库）
- 监听 `127.0.0.1:38080`，用不同 `Host` 头请求同一端口

## 发现

1. **白名单路径的兜底行为需要在 T2 收口。** `/pricing` 在白名单内但 P0 没有实现，于是落到官方 `NoRoute` 返回了官方 index。响应里 tenant 头为空，是因为该头由 ext 的品牌页 handler 设置，兜底路径没经过它；context 里的租户标记其实已写入（测试 `BrandIDForHost` 可证）。**T2 必须保证：品牌域上任何白名单路径都由 ext 响应，绝不落到官方兜底**；否则品牌客户会看到主站页面，违反"OEM 不露平台信息"规则。实现方式：`Routes.Register` 里的早期 handler 对所有白名单路径负责，未实现的返回品牌站 404 页而不是 `c.Next()`。
2. H5 注册的是 `engine.Use(...)` 级别的早期 handler，而不是具体路由，因为官方 `NoRoute` 只能设一次且已被官方占用。这个方式可行，但意味着 ext 的品牌页 handler 在**每个请求**上都会跑一次 `BrandID(c)` 判断（一次 context 读取，无 I/O），可接受。
3. 启动接线需要 `main.go` 一行空白导入 `_ ".../ext"`，这是官方区 import 扩展区的唯一例外，已写入宪法 §2.2 并由 CI 静态扫描兜底（已实测：在 `router/api-router.go` 加 `import ext/brand` 会被 CI 拦截）。
