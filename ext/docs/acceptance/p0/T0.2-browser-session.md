# P0 独立控制台会话验收：真实 Chrome（2026-11-13）

结论：**7 项真实浏览器断言通过；官方登录表单完成后自动跳回独立应用仍待验证，P0 不报完整完成。**

## 运行方式与制品

- 先运行 `web-cmh` 的20项会话/i18n测试与 `typecheck`，均通过；以 `NODE_ENV=production` 重建默认输出 `ext/console/dist`：502.9 kB，gzip165.2 kB。
- 重新编译完整Go实例，将这份资源实际embed到测试二进制。官方 `web/dist` 是本地占位页面，故不得拿它证明官方登录表单可操作。
- 系统Chrome以独立临时profile、headless、loopback调试端口运行；通过原生CDP驱动真实页面/DOM。无用户日常profile，无真实客户数据。
- 全新临时SQLite；官方API完成setup和login，浏览器实际接收Cookie；没有伪造Cookie或绕过服务端会话验证；不输出合成密码或凭据。
- 可复现脚本：`ops/ci/p0-browser-acceptance.mjs`。需要本地38080空库实例与独立Chrome调试端口39222，禁止指向生产。

## 7 项通过

1. 匿名访问 `/cmh/whoami` 实际跳至 `/sign-in?redirect=%2Fcmh%2Fwhoami`。
2. 从同源浏览器调用官方login API签发会话。
3. 全新加载控制台，由实际编译的客户端经官方refresh生命周期取得Bearer，DOM显示合成用户名 `cmhbrowser`。
4. 整页重载后仍能通过官方会话恢复用户名。
5. `document.cookie` 无HttpOnly refresh凭据。
6. localStorage/sessionStorage未发现JWT（仅为本轮有限断言，不声称验证所有秘密格式）。
7. 官方logout后重载再次跳至sign-in。

## 限制与后续

- **没有测试官方登录表单的UI提交与自动回跳**。登录使用同源官方API，之后显式整页导航控制台；这不是把未验证路径算通过。
- 官方sanitizeAuthRedirect接受 `/cmh/whoami`；但官方成功登录使用TanStack `navigate({href: relativeTarget})`，通常只改变SPA路由。官方路由树没有 `/cmh`，可能显示NotFound直到重载。需实际官方Web构建复现后处理，不擅改官方前端或降低验收。
- 本轮HTTP不验证生产Secure Cookie、HTTPS、Origin/CSRF配置。部署前需对应环境验收。
- 客户端未复制认证状态机：直接使用官方导出 `resolveAuthentication/getFreshAuthHeaders/refreshAuthentication/clearAuthentication`，仅固定GET接口可作有界401重试；Token只在官方内存store，不持久化。
- UI17个翻译键覆盖自有7语言；不改官方翻译。复用官方LoadingState；未声明原型已具备完整UI/权限管理。
- Bun未安装，复用pnpm.cmd；使用独立锁文件。类型、20项测试、lint、format与生产构建已由子代理执行，父代理复跑测试/typecheck/默认输出生产构建。
