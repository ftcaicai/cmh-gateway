# OEM 后台第一版操作手册（实施中）

> 当前版本正在接入页面与三库验收，不是整版交付声明。仅在独立开发/测试环境执行。不要使用旧仓库数据库、旧账号密钥或生产 DSN。

## 1. 数据准备

扩展不会在启动或 HTTP 请求中偷偷建表。使用与网关**同一主数据库**的独立迁移命令。品牌档案使用 `cmh_oem_sites` 与 `cmh_oem_site_audits`；客户闭环新增 `cmh_oem_customers`、`cmh_oem_customer_invitations` 与 `cmh_oem_customer_audits`，正在实施和补三库验收。命令不会迁移旧业务数据，也不会创建资金账本。

在 PowerShell 中由操作者安全注入连接串（不要写进仓库、聊天、截图或命令日志），选择数据库类型：

```powershell
# 在当前进程安全设置 CMH_OEM_MIGRATION_DSN 后执行；engine 任选 sqlite/mysql/postgres。
go run ./ext/brand/cmd/oem-migrate -engine sqlite
Remove-Item Env:CMH_OEM_MIGRATION_DSN
```

成功输出 `OEM extension tables ready`。命令可重复执行。失败应停止后续验收；不要把 API 的 `OEM_UNAVAILABLE` 当空列表，也不要直接修改官方数据表来规避。

## 2. 登录和权限

- 使用网关官方登录页及原有浏览器会话，不为 OEM 新建密码系统。
- 工作台入口为 `/cmh/`，品牌页面为 `/cmh/brands`：提供列表、新建、编辑、版本冲突后重新加载和操作记录。品牌阶段真实 Chrome 八项链已通过；客户/目录增量正在单独复验。旧概览/当前账号页面不等于完整 OEM 工作台。
- 接口要求有效的官方浏览器会话和 `cmh_oem` 对应 `read` / `write` Casbin 权限。PAT 和模型调用令牌不作为本组管理接口的身份入口。
- 非 root 管理员默认管理自己创建的品牌；普通用户不会因知道品牌 ID 获得访问权。显式权限拒绝优先于管理员默认权限。禁用账号后原会话应失效。
- root 的身份特权不绕过品牌所有者范围；本版尚未开放跨所有者代管和所有权转移。

## 3. 品牌资料业务

接口：

| 操作 | 方法与路径 |
|---|---|
| 列表 | `GET /api/ext/oem/sites` |
| 创建 | `POST /api/ext/oem/sites` |
| 详情 | `GET /api/ext/oem/sites/:id` |
| 保存 | `PUT /api/ext/oem/sites/:id` |
| 操作记录 | `GET /api/ext/oem/sites/:id/audits` |

创建正文仅接受 `name`、`support_email`、`description` 字符串。保存还必须传当前 `version`。不能提交 `owner_user_id` 或自行选择所有者。

- 名称不能为空、不能带首尾空白；最大 100 UTF-8 字节。
- 邮箱可留空；非空时为普通邮箱地址，不接受显示名；最大 254 字节。
- 说明最大 1000 字节；当前字段不接受换行或其他控制字符。
- JSON 正文最大 8192 字节，未知字段、重复字段（含转义重复）、大小写别名、null/数组根节点均拒绝。
- 每次成功创建/保存与一条操作记录同事务提交；失败不应出现“资料已改但审计没写”的半提交。
- `409 / OEM_VERSION_CONFLICT`：其他窗口已保存，先重新读取并核对，再手动合并；不得自动覆盖或盲目重试。
- `404 / OEM_NOT_FOUND`：记录不存在或不属于当前所有者；不能据此探测其他品牌。
- `400 / OEM_INVALID_INPUT`：修正输入后再提交。
- `503 / OEM_UNAVAILABLE`：检查扩展迁移、数据库就绪情况；响应不会返回数据库 SQL/连接串。

列表和操作记录目前各返回最近最多 100 条，尚未实现翻页；不可当无限量报表使用。

## 4. 第一条验收链

1. 以非 root 管理员登录，创建合成品牌。
2. 刷新并重新打开详情，确认数据来自数据库而不是页面临时状态。
3. 编辑并保存，确认 `version` 加一，操作记录包含创建与更新。
4. 两窗口编辑同一版本，先后保存；后一窗口收到 409 且不能覆盖前者。
5. 第二位管理员通过列表及直接品牌 ID 请求均不能读取、修改或读取审计。
6. 撤销 `cmh_oem` 权限后，原会话立即在下次接口调用被拒绝；恢复默认后再验。
7. 不在截图或验收文件中保留 Bearer、Cookie、连接串或真实客户信息。

## 5. 客户邀请与关系管理

当前服务端已提供以下真实持久化接口，页面及新五表三库正在整合验收：

| 操作 | 方法与路径 |
|---|---|
| 自己品牌的客户列表 | `GET /api/ext/oem/sites/:id/customers` |
| 邀请列表 / 创建邀请 | `GET / POST /api/ext/oem/sites/:id/customer-invitations` |
| 撤销已接受关系 | `POST /api/ext/oem/sites/:id/customers/:user_id/revoke` |
| 客户操作记录 | `GET /api/ext/oem/sites/:id/customer-audits` |
| 本人关系状态 | `GET /api/ext/oem/customer-membership` |
| 本人接受邀请 | `POST /api/ext/oem/customer-invitations/accept` |

管理员只能邀请已存在且启用的普通官方用户，创建正文为 `target_user_id`。系统不创建官方账号、不生成密码、不赋额度，也不查找邮箱或用户名。邀请固定 24 小时，完整高熵 token 只在创建成功时返回一次；列表和审计不提供 token。请经可信私密渠道转交给指定用户，不放 URL、日志、截图或公开群。

指定用户登录自己的官方浏览器会话后，以 `{"token":"…"}` 接受；该本人操作不要求商户管理权限，仍拒绝 PAT/模型令牌。接受将邀请消费、全局唯一客户归属和审计同事务提交。其他用户持有 token 也不能接受。已接受且仍 active 的同一邀请重放只返回同一关系，不重复审计；不同邀请或不同品牌不能静默转移归属。

撤销关系会记录审计并将 active 设为 false，但不删除官方用户、不禁用其 API 令牌或模型调用。撤销后原邀请不可恢复关系，用户归属槽位仍保留；本版不提供转移或重新绑定。收到 409 时不要自动重试或自行改表。

## 6. 目录只读观察

`GET /api/ext/oem/catalog` 返回当前官方用户组的去重排序可见模型 ID，以及 model/destination policy 是否启用两个布尔。界面不提供策略修改、渠道密钥/地址/配置、价格或审批明细。目录不是品牌独享渠道目录，也不是执行许可证明；后续请求仍受官方权限和准入校验。

## 7. 尚未开放的能力

团队分层、客户额度/资金操作及真实 relay 租户隔离未开放。品牌档案和客户关系不是网关账号开通，不提供调用租户隔离保证。尚未批准的 OEM/客户资金同事务、余额充值/划拨、H4/H6、生产品牌域名及旧数据导入均不在此阶段开放。不得以“创建了品牌/接受邀请”推断资金和渠道隔离已完成。
