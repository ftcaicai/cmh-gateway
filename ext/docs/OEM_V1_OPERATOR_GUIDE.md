# OEM 后台第一版操作手册

> 已验收的第一版范围：品牌资料、客户关系与私有备注、已有 Admin 只读协作、本人组只读目录。源码已发布至 main/develop；尚未进行生产部署。仅在独立开发/测试环境执行。不要使用旧仓库数据库、旧账号密钥或生产 DSN。

## 1. 数据准备

扩展不会在启动或 HTTP 请求中偷偷建表。使用与网关**同一主数据库**的独立迁移命令。品牌档案使用 `cmh_oem_sites` 与 `cmh_oem_site_audits`；客户闭环另用 `cmh_oem_customers`、`cmh_oem_customer_invitations` 与 `cmh_oem_customer_audits`，私有备注使用 `cmh_oem_customer_notes`。已发布 `0ac685b39` 的六表已通过真实三库 fresh/升级/重复迁移；当前团队源码新增 `cmh_oem_team_invitations`、`cmh_oem_team_members`、`cmh_oem_team_audits`，九表已通过 SQLite 3.50.4 / MySQL 8.0.44 / PostgreSQL 17.12 fresh 与前版六表含数据升级各两次、独立连接重读及 CAS/回滚验收，不沿用前版证据。命令不会迁移旧业务数据，也不会创建资金账本。

在 PowerShell 中由操作者安全注入连接串（不要写进仓库、聊天、截图或命令日志），选择数据库类型：

```powershell
# 在当前进程安全设置 CMH_OEM_MIGRATION_DSN 后执行；engine 任选 sqlite/mysql/postgres。
go run ./ext/brand/cmd/oem-migrate -engine sqlite
Remove-Item Env:CMH_OEM_MIGRATION_DSN
```

成功输出 `OEM extension tables ready`。命令可重复执行。失败应停止后续验收；不要把 API 的 `OEM_UNAVAILABLE` 当空列表，也不要直接修改官方数据表来规避。

## 2. 登录和权限

- 使用网关官方登录页及原有浏览器会话，不为 OEM 新建密码系统。
- 工作台入口为 `/cmh/`，品牌页面为 `/cmh/brands`、客户关系页面为 `/cmh/customers`、只读目录为 `/cmh/catalog`。发布增量 `a145f48dc` 的最终组合 Chrome 14 项已通过，包括实际保存、刷新、409、独立客户身份接受及撤销；合成会话验收不等同真人密码/MFA 登录或生产 TLS 验收。
- 接口要求有效的官方浏览器会话和 `cmh_oem` 对应 `read` / `write` Casbin 权限。PAT 和模型调用令牌不作为本组管理接口的身份入口。
- 非 root 管理员默认管理自己创建的品牌；普通用户不会因知道品牌 ID 获得访问权。显式权限拒绝优先于管理员默认权限。禁用账号后原会话应失效。
- root 的身份特权不绕过品牌所有者范围；本版尚未开放跨所有者代管和所有权转移。

## 3. 品牌资料业务

接口：

| 操作 | 方法与路径 |
|---|---|
| 列表 | `GET /api/ext/oem/sites` |
| 创建 | `POST /api/ext/oem/sites` |
| 详情 | `GET /api/ext/oem/sites/:id` |
| 保存 | `PUT /api/ext/oem/sites/:id` |
| 操作记录 | `GET /api/ext/oem/sites/:id/audits` |

创建正文仅接受 `name`、`support_email`、`description` 字符串。保存还必须传当前 `version`。不能提交 `owner_user_id` 或自行选择所有者。

- 名称不能为空、不能带首尾空白；最大 100 UTF-8 字节。
- 邮箱可留空；非空时为普通邮箱地址，不接受显示名；最大 254 字节。
- 说明最大 1000 字节；当前字段不接受换行或其他控制字符。
- JSON 正文最大 8192 字节，未知字段、重复字段（含转义重复）、大小写别名、null/数组根节点均拒绝。
- 每次成功创建/保存与一条操作记录同事务提交；失败不应出现“资料已改但审计没写”的半提交。
- `409 / OEM_VERSION_CONFLICT`：其他窗口已保存，先重新读取并核对，再手动合并；不得自动覆盖或盲目重试。
- `404 / OEM_NOT_FOUND`：记录不存在或不属于当前所有者；不能据此探测其他品牌。
- `400 / OEM_INVALID_INPUT`：修正输入后再提交。
- `503 / OEM_UNAVAILABLE`：检查扩展迁移、数据库就绪情况；响应不会返回数据库 SQL/连接串。

品牌操作记录、客户列表、客户操作记录与团队操作记录按时间倒序分页：接口接受 `?offset=&limit=`（`limit` 上限 100，缺省或非法值按首页 100 条），后台每次加载 50 条并提供"加载更多"。品牌列表、邀请列表与团队成员仍为最近 100 条，不翻页；不可当无限量报表使用。

## 4. 第一条验收链

1. 以非 root 管理员登录，创建合成品牌。
2. 刷新并重新打开详情，确认数据来自数据库而不是页面临时状态。
3. 编辑并保存，确认 `version` 加一，操作记录包含创建与更新。
4. 两窗口编辑同一版本，先后保存；后一窗口收到 409 且不能覆盖前者。
5. 第二位管理员通过列表及直接品牌 ID 请求均不能读取、修改或读取审计。
6. 撤销 `cmh_oem` 权限后，原会话立即在下次接口调用被拒绝；恢复默认后再验。
7. 不在截图或验收文件中保留 Bearer、Cookie、连接串或真实客户信息。

## 5. 客户邀请与关系管理

以下真实持久化接口及对应页面已完成组合验收；五表三库的独立验证见客户与目录验收记录：

| 操作 | 方法与路径 |
|---|---|
| 自己品牌的客户列表 | `GET /api/ext/oem/sites/:id/customers` |
| 邀请列表 / 创建邀请 | `GET / POST /api/ext/oem/sites/:id/customer-invitations` |
| 撤销已接受关系 | `POST /api/ext/oem/sites/:id/customers/:user_id/revoke` |
| 客户操作记录 | `GET /api/ext/oem/sites/:id/customer-audits` |
| 本人关系状态 | `GET /api/ext/oem/customer-membership` |
| 本人接受邀请 | `POST /api/ext/oem/customer-invitations/accept` |

管理员只能邀请已存在且启用的普通官方用户，创建正文为 `target_user_id`。系统不创建官方账号、不生成密码、不赋额度，也不查找邮箱或用户名。邀请固定 24 小时，完整高熵 token 只在创建成功时返回一次；列表和审计不提供 token。请经可信私密渠道转交给指定用户，不放 URL、日志、截图或公开群。

指定用户登录自己的官方浏览器会话后，以 `{"token":"…"}` 接受；该本人操作不要求商户管理权限，仍拒绝 PAT/模型令牌。接受将邀请消费、全局唯一客户归属和审计同事务提交。其他用户持有 token 也不能接受。已接受且仍 active 的同一邀请重放只返回同一关系，不重复审计；不同邀请或不同品牌不能静默转移归属。

撤销关系会记录审计并将 active 设为 false，但不删除官方用户、不禁用其 API 令牌或模型调用。撤销后原邀请不可恢复关系，用户归属槽位仍保留；本版不提供转移或重新绑定。收到 409 时不要自动重试或自行改表。

## 6. 客户私有备注（已发布增量）

商户管理备注与客户本人关系状态分离：`GET / PUT /api/ext/oem/sites/:id/customers/:user_id/notes`，仅具有相应 OEM 权限且拥有该品牌的商户访问。响应为 `note`、`version`、`updated_at`；无备注时返回空字符串、版本 0。保存只提交 `{"note":"…","version":0}`，首次创建后使用当前版本更新；冲突应重新读取后人工合并，禁止自动覆盖。

备注最大 2000 UTF-8 字节，允许换行和制表符，拒绝其他控制字符；不是富文本，不渲染 HTML。备注仅出现在商户专用接口，不加入客户本人 membership 或邀请/列表响应。备注写入及 `customer.note_updated` 审计同事务，审计不记录正文。撤销关系后的历史客户仍归原商户，可保留和维护私有备注；这不恢复关系或模型调用控制。六表新建与已有五表升级的真实三库重复迁移、备注 CAS 和回滚已通过；页面客户端 35 项测试与构建通过，最终实际 Chrome 组合 20 项全部通过，包括真实备注保存、刷新、冲突及迟到响应隔离。该增量已随 `0ac685b39` 发布，团队仍在实施；合成会话验收不代表生产 TLS 或真人登录验证。

团队已获批准的下一步仅限**已有官方 Admin 的只读协作**：目标必须事先由平台独立授权并本人接受邀请；共享指定品牌/客户读取，不共享私有备注，不开放客户关系修改或品牌编辑。所有者管理邀请和撤销，撤销后旧会话的下次请求不能继续读取；不追溯取消已经授权的在途响应。后端及九表真实三库、页面 39 项测试/type/lint/build 已通过，独立后端/UI 人工复核无具体阻断；最终组合 Chrome 28 项全部通过（包含前版 20 项），撤销后原成员会话新请求 404、冷加载列表移除均实测。团队增量已验收，发布提交记录见实施入口。不要为普通员工升全局 Admin 来模拟团队权限。

团队接口（验收完成前仅用于隔离开发环境）：

| 操作 | 方法与路径 |
|---|---|
| 所有者成员列表 | `GET /api/ext/oem/sites/:id/team` |
| 所有者邀请列表 / 创建 | `GET / POST /api/ext/oem/sites/:id/team-invitations` |
| 所有者撤销 | `POST /api/ext/oem/sites/:id/team/:user_id/revoke` |
| 所有者团队审计 | `GET /api/ext/oem/sites/:id/team-audits` |
| Admin 本人接受 | `POST /api/ext/oem/team-invitations/accept` |

邀请正文仅 `target_user_id`，接受仅 `token`，撤销必须提交成员当前 `version`。邀请固定 24 小时，仅创建时返回一次完整 token，使用私密渠道交给目标。目标必须在接受及后续共享读取时仍为启用的官方 Admin，且仍有真实 OEM 读取权限。共享品牌列表/详情的 `access` 为 `owner` 或 `readonly`，仅为界面能力提示，服务端仍独立验证每一请求。

撤销不删除官方账号或降级全局角色。旧已接受邀请和撤销前未消费邀请不能重新激活关系；所有者须在撤销后另发新邀请，并由目标再次接受。协作者无权查看团队管理信息、客户邀请元数据、私有备注或执行任何品牌/客户写操作。root 也不绕过品牌关联范围。

## 7. 目录只读观察

`GET /api/ext/oem/catalog` 返回当前官方用户组的去重排序可见模型 ID，以及 model/destination policy 是否启用两个布尔。界面不提供策略修改、渠道密钥/地址/配置、价格或审批明细。目录不是品牌独享渠道目录，也不是执行许可证明；后续请求仍受官方权限和准入校验。

## 8. 品牌域客户登录（H8，默认关闭，仅测试环境）

品牌域可让**该品牌的有效客户**用官方账号密码（及已启用的两步验证码/备用码）直接登录，登录后只有“我的账号”最小资料页。会话与登录流程在创建时与品牌站点、精确来源和发起浏览器绑定：主站、其他品牌、其他浏览器都不能使用它；主站会话也不能用于品牌域。

开启步骤（顺序不可调换）：

1. 停止网关。
2. 运行迁移并回填主站绑定（开启后，没有绑定记录的会话和登录流程一律拒绝，所以现有主站会话必须先回填）：

   ```powershell
   # 已在当前进程设置 CMH_OEM_MIGRATION_DSN
   go run ./ext/brand/cmd/oem-migrate -engine sqlite -backfill-main-auth
   ```

   输出 `main-site auth bindings added: N` 与 `OEM extension tables ready`。命令可重复执行，不覆盖已有绑定。
3. 设置 `CMH_BRAND_PROTOTYPE_HOSTS="品牌域名=品牌ID"`（品牌 ID 为 `/cmh/brands` 中 32 位站点 ID，可逗号分隔多个）与 `CMH_BRAND_AUTH=1`，再启动网关。所有节点必须同时切换，不支持新旧二进制混跑。

使用限制：

- 品牌域必须经 HTTPS 访问；登录、刷新、退出请求的 `Origin` 必须与品牌域完全一致。域名到品牌的映射目前只来自上述环境变量，DNS 归属验证与证书签发尚未实现，不得用于生产域名。
- 只有 `/cmh/customers` 中关系为有效的客户可以登录；品牌所有者和团队成员仍在主站登录。撤销客户关系后，其品牌会话在下一次请求时失效。非本品牌客户即使密码正确，得到的也是与密码错误相同的提示。
- 品牌域不提供注册、找回密码、第三方登录和 Passkey。账号的登录验证只有 Passkey 时无法在品牌域登录（不会降级为免验证）。品牌域不接受访问令牌，也不提供模型调用入口。
- **未解决：** `SESSION_COOKIE_SECURE=true` 且 TLS 在反向代理终止时，官方来源守卫会拒绝品牌域的刷新与退出（403 `AUTH_ORIGIN_FORBIDDEN`），除非把品牌来源加入 `SESSION_COOKIE_TRUSTED_URL`；这会让品牌来源同时对主站的刷新/退出受信。该守卫不在已批准修改的官方文件内，正式启用前需负责人决定处理方式。
- 主站开启 Turnstile 时，品牌登录页自动显示同一站点密钥的人机验证组件，未通过验证不能提交；该页的 CSP 会额外放行 `challenges.cloudflare.com`，其他品牌页不受影响。Cloudflare 的站点密钥需把品牌域名加入允许的主机名列表，否则组件显示域名错误。此接入只在自动化测试里核对了页面输出与 CSP，没有在真实浏览器和真实密钥下操作过。
- 两步验证码通过后若会话绑定写入失败，登录不会成功，但该验证码或备用码已被使用，需重新登录并使用下一个验证码。
- **关闭前先撤销品牌会话。** 未开启时官方代码不再读取绑定，尚未过期的品牌会话会被主站当作普通会话接受。关闭步骤：停止网关 → `go run ./ext/brand/cmd/oem-migrate -engine <类型> -revoke-brand-sessions`（输出 `brand sessions revoked: N`）→ 若使用 Redis，等待用户缓存 TTL 过期或清除会话缓存 → 去掉 `CMH_BRAND_AUTH` 后启动。兜底：系统任务 `cmh_auth_scope_maintenance` 每分钟在主节点运行，发现 `CMH_BRAND_AUTH` 未开启而仍有未过期的品牌绑定会话时自动撤销（原因 `brand_auth_disabled`），因此漏掉撤销步骤的暴露窗口最多约一分钟加任务调度延迟，而不是直到会话过期；该任务不替代上述步骤，Redis 缓存仍需等待 TTL。
- 开启后主站每个已登录请求多一次绑定查询；本批没有绑定缓存。过期的绑定行由同一系统任务每分钟清理。

## 9. 域名自助接入（仅测试环境）

商家在 `/cmh/brands` 打开自己的品牌，在“自有域名”里填写域名并保存，页面给出一条 CNAME 记录；商家在域名服务商处添加后，网关每分钟自动检查，解析精确匹配即生效，所有节点无需重启。每个品牌一个域名；更换或移除域名后原域名立即失效，新域名需重新验证。

运营方准备（一次）：

1. 运行 `go run ./ext/brand/cmd/oem-migrate -engine <类型>`，新增 `cmh_oem_site_domains` 表。
2. 选一个接入根域，例如 `brands.example.com`，把通配解析 `*.brands.example.com` 指向网关入口。
3. 以**进程环境变量**设置后启动网关（`CMH_BRAND_AUTH` 只能用进程环境变量，写在 `.env` 里不生效；下面两个变量两种方式都可以）：
   - `CMH_BRAND_CNAME_ROOT=brands.example.com`：未设置时商家页面显示“尚未开启自有域名接入”。
   - `CMH_PLATFORM_DOMAINS=example.com`：平台自有域名，逗号分隔；这些域名及其子域不能被商家认领。接入根域自动受保护。

证书：网关自身不终止 TLS，也不签发证书。由前置反向代理按需签发，签发前询问网关 `GET /api/ext/brand/tls-allowed?domain=<域名>`，返回 200 才允许（仅已验证的品牌域名与静态映射的域名）。Caddy 示例：

```
{
    on_demand_tls {
        ask http://127.0.0.1:3000/api/ext/brand/tls-allowed
    }
}
https:// {
    tls {
        on_demand
    }
    reverse_proxy 127.0.0.1:3000
}
```

说明与限制：

- 原有的 `CMH_BRAND_PROTOTYPE_HOSTS` 仍可用于本地开发（如 `brand.localhost`），优先于数据库映射。
- 只有品牌所有者能查看和修改域名；只读协作成员看不到。修改域名目前只要求登录会话与 OEM 写权限，**没有二次密码确认**（旧系统有）。
- 已生效的域名每 24 小时复查一次（与每分钟的待验证检查同一系统任务，每轮最多 20 个）。CNAME 被删除或指向别处时域名立即停止服务，操作记录写入"域名 CNAME 已失效"，页面显示未生效及原因；CNAME 目标不变，商家恢复记录后下一轮自动重新生效，无需再次保存。解析超时等临时故障只顺延下次复查，不下线域名。
- **HTTPS 就绪**：域名验证通过后，同一系统任务对该域名做一次真实的 TLS 握手（校验证书链与主机名），结果在"自有域名"里显示为"HTTPS 已就绪"及证书到期日，或未就绪的原因；未就绪每 10 分钟重试，就绪后每天复查，证书 14 天内到期时提示。探测前先解析域名，解析到内网、回环、链路本地等非公网地址时不连接并显示"解析到内网地址"。结果仅作提示，不影响域名是否提供服务。"立即检查 HTTPS"会同时重查。
- **暂停站点**：所有者可在"站点状态"里暂停，该品牌所有域名（含自有域名与本地映射）的页面返回 403 并显示"站点已暂停服务"，接口返回 `{"code":"brand_site_suspended"}`，样式与 Logo 仍可加载；客户账号与会话不变但无法在品牌域使用。恢复后立即可用，经同步主题传到所有节点。证书续期不受影响。平台侧（跨所有者）暂停尚未开放。
- 国际化域名需填写 punycode 形式。

## 10. 外观与 SEO

品牌所有者在 `/cmh/brands` 打开自己的品牌，在“外观与 SEO”里设置；只读协作成员看不到。先运行一次 `oem-migrate`（新增 `cmh_oem_site_appearances` 与 `cmh_oem_site_logos` 两张表）。

- **网站风格**：云白商务、暗夜科技、暖白杂志（标识沿用旧系统的 `default` / `technology` / `business`）。保存后品牌站所有页面立即切换。
- **Logo**：PNG、JPEG 或 WebP，不超过 1 MB、2048 × 2048 像素；服务端完整解码后才保存，文件名和声明的类型不被信任。上传后显示在页头并作为浏览器图标；“恢复默认标识”即移除。
- **基础 SEO**：网站标题（120 字）、描述（300 字）、关键词（200 字），单行文本。标题留空用品牌名称，描述留空用品牌档案的描述；内页标题自动加页面名前缀。内容经转义后写入 `title`、`description`、`keywords` 与 Open Graph 标签，不能插入脚本、HTML 或站长验证代码。
- **收录开关**：允许时首页、模型价格、接入文档可被收录；关闭后所有页面 `noindex`、`/robots.txt` 禁止抓取、`/sitemap.xml` 为空。登录与账号页面始终 `noindex`。
- **规范地址**：只来自已验证的自有域名；没有验证域名时不输出 canonical，网站地图为空。

主题与 SEO 一起保存并带版本校验：两人同时修改时后保存的一方会被提示重新加载。Logo 上传、移除与外观保存都写入品牌的操作记录。

- **预览**：外观面板的"预览"按当前所选（可未保存）主题，配合已保存的标题、Logo 与档案，渲染首页、接入文档、登录三页；在无任何权限的沙箱框架中显示，不执行脚本，也不保存任何内容。模型价格页依赖脚本加载数据，不提供预览。
- **主题构图**：云白商务为左右双栏；暗夜科技为居中大标题、渐变强调色、三栏特性卡片与圆角按钮；暖白杂志为衬线大标题、斜体强调、竖线分隔的编号列表、方角按钮，价格页为整行列表，登录页左右互换。窄屏下均改为单栏。
- **Logo 历史**：替换或移除 Logo 时，原 Logo 进入历史，保留最近 3 个，可在面板中一键恢复（恢复时当前 Logo 也进入历史）；写入"已恢复 Logo"操作记录。
- **页脚署名**：每个品牌站页面页脚保留"Powered by new-api · QuantumNous · AGPL-3.0"，这是 AGPL 要求的唯一平台相关字样，禁词测试会断言其存在。

与旧系统的差距：Logo 仍存在主数据库里；预览不含价格页。
