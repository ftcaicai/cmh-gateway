# RFC：挂载点 H2 TenantResolver 与 H5 RouteRegistrar

- 日期：2026-11-13
- 状态：已批准（P0 T0.3 原型验证，负责人指令"继续"）
- 涉及登记：`ext/docs/HOOKS.md` H2、H5

## 要解决的问题

OEM 品牌站按 Host 区分租户：品牌域名的请求必须在进入任何官方路由之前被识别（写入 context）并受路径白名单约束；品牌页面、品牌 API、`/cmh/*` 静态资源等扩展路由需要注册到 gin 引擎。官方代码没有任何"外部注册路由"或"外部中间件"的入口。

## 为什么非侵入方式做不到

| 方式 | 结论 |
|---|---|
| 插件 | 插件只处理模型请求的协议转换，不能注册 HTTP 路由或全局中间件 |
| `ext/` 独立实现 | gin 引擎由官方 `main.go` 创建并直接 `Run`，扩展区拿不到引擎实例；另起一个进程/端口会失去官方 session、鉴权和计费 |
| 现有挂载点 | R1、R2 均为非代码 |

## 改动内容

| 挂载点 | 文件 | 位置 | 改动 | 行数 |
|---|---|---|---|---|
| H2 | `main.go` | `server.Use(middleware.RequestId())` 之后、`middleware.Version()` 之前 | `server.Use(core.TenantMiddleware())` | +1 |
| H5 | `router/main.go` | `SetRouter` 内、`SetWebRouter` / `NoRoute` 分支之前 | `core.RegisterRoutes(router)` | +1 |
| import | 两文件各加一行 `extcore "github.com/QuantumNous/new-api/ext/core"` | | +2 |

合计 **4 行**。

### 为什么 H2 放在 `RequestId()` 之后而不是最前

`PanicRecover` 和 `RequestId` 是官方的基础设施中间件，租户解析要能拿到 request id 以便日志关联，且自身 panic 也应被官方的 recover 兜住。放在 `Version()`、`I18n()` 之前，是因为品牌域的 421/404 响应不需要这两者。

### 为什么 H5 放在 `SetWebRouter` 之前

官方 `SetWebRouter` 注册的是 `NoRoute`（兜底）。gin 的具体路由永远优先于 `NoRoute`，所以 ext 注册的 `/api/brand/*`、`/cmh/*` 等只要在引擎上注册就会生效，与顺序无关；但放在 `SetWebRouter` 之前能让 ext 在需要时**先于官方兜底**挂自己的 `NoRoute` 逻辑链（品牌域渲染品牌页而非官方 index）。官方 `NoRoute` 只能设置一次，ext 不覆盖它，而是通过 H2 中间件在品牌域上直接写响应并 `Abort`。

## 依赖方向

`main.go` 与 `router/main.go` import 的是 `ext/core`（只含接口与默认实现，零业务依赖）。`ext/core` 不 import 官方任何业务包，不形成环。`ext/`（业务）import 官方包，并在 `ext.Register()` 中替换 `core` 的变量。官方区不 import `ext/`。

## 默认行为

`core.TenantMiddleware()` 默认实现：直接 `c.Next()`。
`core.RegisterRoutes()` 默认实现：空操作。
去掉 `ext.Register()` 调用后，官方行为与上游逐字节一致。

## 对同步的影响

两处均为单行插入，位于官方很少改动的位置（中间件链、路由入口）。若官方重排中间件顺序，冲突在 1 行内可解。
