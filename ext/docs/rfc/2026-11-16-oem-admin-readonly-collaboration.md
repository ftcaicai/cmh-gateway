# OEM 第一版：已有 Admin 的只读品牌协作

日期：2026-11-16。状态：用户已明确批准有限实施；源码设计中，未实现、未验收。

## 用户决定

在“已有 Admin 只读协作 / 普通员工先设计权限扩展 / 本版不含团队”中，用户选择前者。仅邀请已经由平台独立授予官方 Admin 权限的账号，目标本人以官方浏览器会话接受。指定品牌及客户读取可共享；品牌所有者管理邀请和撤销。该批准不是普通员工提权、资金、官方账号操作或 relay 租户隔离授权。

## 必须维持的授权边界

- 所有请求复用官方会话及真实 Casbin OEM read/write 权限；不能改写请求 actor 为 owner，不能为普通用户临时伪装 Admin。
- 读取还须同时满足品牌所有者或该品牌活跃协作关系。跨品牌成员身份无效，撤销后旧会话也不得继续读取。
- 共享范围限品牌资料、客户列表及固定操作记录；客户私有备注仍仅所有者，邀请令牌/摘要不共享。品牌编辑、客户邀请/撤销、备注读写、团队管理均不因只读协作取得权限。
- 邀请绑定品牌/所有者/目标，固定有限有效期、高熵令牌仅持久化摘要；本人接受、关系变更及无机密审计同事务。重复接受只允许同一仍有效关系，不让已撤销旧邀请重新激活。
- 使用独立 cmh_* 关系表，不新建角色/密码体系，不修改官方用户表或角色。迁移显式执行，新增表必须重新真实三库 fresh/upgrade/repeat/reopen 验收。

## 为什么不直接做普通员工

当前 service/authz/assignment.go 仅从系统 root/admin 派生角色；resolver.go 在 per-user override 前拒绝空角色；SetUserPermissions(true) 不会为普通用户创造 Admin 基线权限。旧系统层级不能原样复制成新角色表。真正普通员工权限仍需独立授权架构方案，不能静默移除 RequirePermission。

## 验收门槛

所有者/协作者/其他 Admin/普通用户/PAT/过期及撤销会话正反例；跨品牌 404；共享读取不开放任何写或私有备注；接受/撤销 CAS 及审计回滚；真实三库迁移与唯一约束；页面邀请、本人接受、只读访问和撤销后拒绝的实际浏览器闭环。以上目前均为待执行，不因批准或构建成功视为已通过。
